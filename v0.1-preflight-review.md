# AEG v0.1 Senior Full-Stack Preflight Review

> Date: 2026-08-17  
> Decision: `GO_FOR_LOCAL_IMPLEMENTATION`  
> Authority: `v0.1-mvp-contract.md`, `v0-closure-review.md`, `v0-specification.md`

## 1. Current baseline

- The repository is on `master` with no commits and no configured remote. Existing documents, research material, and `spike/` are untracked pre-existing assets.
- The disposable spike is evidence only. Its JavaScript implementation is excluded from production code reuse.
- The controlled Node runtime is v24.19.0. TypeScript and a YAML parser are not currently available in the workspace.
- No real GitHub Actions identity, workflow run, or independent CI metadata is available. Real E2 remains `unverified`.

## 2. User and business outcome

The deliverable is a local, deterministic verifier that converts supported evidence into one canonical profile and emits a minimal report plus a CI-consumable exit code. It gives maintainers a reproducible gate over evidence delivery; it does not prove code correctness, test sufficiency, runner integrity, market demand, or real E2 production assurance.

The nearest external milestone is a reviewable, locally verified MVP repository. GitHub publication, release creation, and Fund submission are outside this implementation decision and require a later explicit confirmation.

## 3. Scope and architecture

The implementation boundary is:

`OMK v3 adapter | maintainer-CI adapter -> canonical profile -> deterministic policy engine -> JSON report -> Markdown/terminal/exit code`

- Inputs: `agent-task.yml`, `agent-trace.jsonl`, Git facts, and one external producer/trust context.
- Profiles: `local`, `pr`, and `protected`; declarations C0-C2; assurance E0-E3 semantics with only E0/E1/E2-candidate executable in v0.1.
- Policies: AEG001, AEG002, AEG003, AEG010, AEG020, AEG021, AEG022, AEG030, AEG031, AEG040, AEG050, AEG060, AEG061, and AEG070.
- Outputs: canonical JSON is authoritative; Markdown and terminal output only render it. Public fields are allowlisted.
- Excluded: dashboard, service, database, telemetry, third adapter, automatic remediation, candidate-code execution, LLM/API calls, runtime network access, secrets, receipt hash, ledger, replay database, and a new OMK control plane.

## 5. Data, security, and privacy decisions

1. The verifier never runs `argv`, `cwd`, test commands, scripts, npm, builds, or any PR-provided executable content. Those fields are compared as inert structured data only.
2. All parsers enforce the closed input limits before full processing: manifest 1 MiB, trace 20 MiB, JSONL line 256 KiB, 50,000 events, path length 4,096, JSON depth 20. Exceeding a limit is a stable fail without echoing input.
3. E1 never upgrades to E2-candidate solely from producer claims. E2-candidate requires independently supplied, configured trust context plus compatible repository/head/workflow/check/state facts. It remains explicitly non-production-proven.
4. State binding uses a versioned compatibility fingerprint over verifier-observable Git facts. It is not a signature, receipt replacement, or tamper-proof attestation.
5. Reports never contain raw command, cwd, prompt, source, stdout/stderr, environment values, credentials, or raw parser error text. Fixtures and documentation use synthetic data only.

## 6. Resource and dependency budget

| Resource | Budget and validation |
| --- | --- |
| Runtime model/API/network | 0; tests assert no runtime request path exists |
| Runtime dependencies | Prefer 0 except a pinned, bundled YAML parser if required by the manifest contract; license, lockfile, integrity, and offline bundle verification required |
| Build dependencies | TypeScript compiler and bundler may be dev-only, pinned and locked; no install occurs in Action execution |
| Input work | Limits in section 5; fail closed before allocation/iteration beyond each bound |
| Code surface | One core package, two thin adapters, one CLI, one Action wrapper; no third adapter |
| Test cost | Single deterministic fixture suite; fixture generation is static and repeated runs compare byte output rather than invoking agents or code under test |

The immediate efficiency priority is a single canonical policy pipeline and shared fixture factory so adapters do not duplicate logic or test matrices. Current cost is two source shapes and three profiles creating repeated cases. Expected improvement is one engine invocation per fixture with adapter equivalence tests; validation is that both adapters map to identical canonical policy results where the input semantics match.

## 7. Implementation checkpoints and exit criteria

1. **Schema/preflight:** TypeScript project, immutable limits, safe YAML/JSONL loaders, canonical error report, and negative boundary tests.
2. **Git/state:** read-only Git facts, normalized path handling, compatibility fingerprint, and stale/unknown/dirty negative tests.
3. **Policy:** complete AEG001-AEG070 coverage across the three profiles, without adapter-specific branches.
4. **Integration:** OMK v3 and maintainer-CI adapters, CLI, authoritative JSON renderer, Markdown renderer, stable exit codes.
5. **Acceptance:** F01-F28 and I00-I15 automated; false-pass rate 0, traceability 100%, byte-identical replay, zero sentinel leaks.
6. **Action/docs:** static Action safety verification, synthetic demo, threat model, limits, rollback and unverified-E2 disclosure.

The first verifiable delivery is checkpoint 1: a TypeScript skeleton with a bounded manifest/trace preflight and a stable failure report tested against malformed, oversized, and privacy-sentinel fixtures. It creates no external side effects.

## 8. Rollback and stop conditions

- Local rollback: implementation files can be removed or reverted without migrating data because the product stores no state and this repository has no release or remote yet.
- Future Action rollback: remove the Action reference or pin to a prior immutable release; reports remain parseable by their schema version.
- Stop immediately and report before further feature work if a path executes untrusted content, exposes a secret/private sentinel, permits a false pass in a required negative case, introduces nondeterministic verdicts, or requires real E2 claims without independent evidence.
- A missing local compiler/parser is a dependency-resolution issue, not a reason to relax the YAML or TypeScript contracts. It must be solved with pinned, reviewed build dependencies before implementation proceeds.

## 9. Preflight decision

**GO_FOR_LOCAL_IMPLEMENTATION.** The frozen product scope is internally coherent and can be implemented locally. The residual risks—unverified real E2, unvalidated adoption, and future Action misconfiguration—are documented and do not authorize misleading claims or external publication. Code may start only inside the boundaries above.
