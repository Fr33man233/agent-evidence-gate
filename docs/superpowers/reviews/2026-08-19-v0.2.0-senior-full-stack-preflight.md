# AEG v0.2.0 资深全栈开发前预检

**日期：** 2026-08-19  
**设计依据：** [原生 OMK Receipt v3 设计](../specs/2026-08-19-native-omk-receipt-v3-design.md)  
**基线：** `ddea99a5a9860f750151f2e28b45fbd077f27b92`（公开稳定版本仍为 `v0.1.3`）

## 决策

**GO（仅限隔离工作树中的 v0.2.0 实现与本地验证）。** 未满足下列退出标准前，发布、Marketplace 更新、tag、Release、公开分支更新和试点外部写入均为 **NO-GO**。

## 价值、范围与体验

维护者将得到离线、确定性的本地门禁：直接校验 `open-multi-agent-kit@0.96.0` 的 EvidenceReceipt v3，将选中的 Receipt、独立 AEG trace 与当前 Git 工作区绑定，并输出 E1 JSON、Markdown 与退出码。核心可验证流程为“通过 → 覆盖文件变更后过期失败 → 重跑 OMK 后再次通过”。

CLI 与只读 Action 是全部交互面；不新增 GUI、服务、数据库、模型、网络或自动 trace 转换。`local` 是唯一可通过 profile；`pr` 和 `protected` 只可输出 E1 限制导致的 advisory failure，绝不宣传为独立 CI 或 E2。

## 架构、合同与边界

输入合同固定为 `aeg-task/v2`、`aeg-trace/v1`、一个 Receipt 或 OMK store 根目录及 Git 仓库。`required_checks` 使用结构化 `shell` 或 `argv` command descriptor 和安全仓库相对 `cwd`；绝不从 claim prose 推断命令或成功。

实现删除 v0.1 自定义 envelope、`source.kind` 路由、`maintainer_ci` 能力、`trust_context` 与 `--evidence`。新增的 Receipt 兼容模块仅复现 OMK v3 的 canonical JSON/domain-separated core digest 校验与状态采集规则；不会创建 receipt、ledger、replay database、runner 或执行控制面。

运行时只读取有界本地文件与受限 Git 事实；不执行 Receipt、候选代码、候选 package、test 或 script，不使用 `pull_request_target`、secrets、credential store、运行时 package installation、LLM、API 或网络。输入 link、junction、reparse point、scope escape、未知 schema、重复 JSON key 和任何不安全/含隐私内容的字段都失败封闭；报告仅使用固定摘要和稳定 ID。

## 资源效率审查

| 分类 | 当前成本 | 决策 | 目标与验证 |
| --- | --- | --- | --- |
| 两套输入模型 | envelope adapter 与原生 Receipt 会造成重复解析、测试和错误信任路径 | **remove** | 删除 v0.1 adapter/envelope；静态搜索和替换矩阵证明不存在 public runtime 路径 |
| 依赖布局 | 当前隔离 worktree 无 `node_modules`，源工作树已有依赖；跨 worktree junction 曾导致 esbuild 解析失败 | **optimize now** | 先记录真实布局；只采用可重复的受控依赖解析或隔离 `pnpm install --frozen-lockfile --ignore-scripts`，不把解析失败登记为 build 通过 |
| Receipt 校验 | 完整 OMK 包体积和依赖不适合 Action bundle | **optimize now** | 零新增生产依赖，使用已审查的 sanitizer fixture 与独立 vector；禁止打包 OMK |
| 回归验证 | 重复完整构建/端到端测试浪费时间 | **optimize now** | 每个切片先跑单一失败/通过测试；只在接口切片完成后跑全套；完整测试目标不超过 5 秒、超过 10 秒调查 |
| E2、ledger、其他 adapter | 会扩大可信边界且不能服务最近本地试点 | **defer** | v0.2 不实现；任何重新引入须新版本独立任务和设计 |

资源硬边界：生产依赖总数最多 1；每个 CLI/Action bundle 目标不超过 500 KiB、硬上限 1 MiB；单 Receipt 最多 1 MiB、每次最多 64 张/总计 8 MiB、JSON 深度最多 32；运行时 model/API/network 为 0。

## 测试、运维、部署与回滚

实施按 schema/preflight、Receipt parser/vector、workspace 状态绑定、goal/check/trace 选择、policy/report v2、CLI/Action、F/I regression、文档/本地试点、RC 审计顺序进行。每个生产变更前必须先新增并观察相应失败测试；安全、确定性与隐私 sentinel 用负向 fixture 覆盖。

Action 迁移至 Node 24 前，静态检查必须证明没有触发器、secrets、shell、package installation、network 或 candidate execution 路径；受控合成运行仅在构建和其余本地证据均通过后考虑。真实 maintainer CI/E2、第三方安全审计均保持未验证。

回滚不涉及数据库或数据迁移：保留 `v0.1.3` tag、Release、Marketplace alias 与 `main` 不变。出现 P0 隐私、安全、确定性或数据边界问题时立即停止版本推进，保留最后一次已验证本地 commit；不得降低门禁以换取试点通过。Receipt、trace、report 均为本地 disposable 文件，必须被忽略而非提交。

## 退出标准

实现阶段退出需要：旧信任升级路径与 adapter 已移除；官方固定 v0.96.0 sanitized fixture 与所有 schema/digest/command/goal/trace/state/privacy 负例通过；全部 Receipt 始终是 E1；JSON/Markdown 字节级确定；privacy sentinel 零泄露；静态和动态检查均无 runtime network/model/secret/package/candidate-command 路径；依赖、bundle、测试时长与 Node 24 Action 预算符合；本地试点完成核心三步；独立审查无 P0/P1。

## 风险登记

| 风险 | 分类 | 处理与停止条件 |
| --- | --- | --- |
| OMK canonicalization/workspace digest 与 0.96.0 不一致 | **risk** | 对固定官方 fixture/vector 对照；任何不一致停止该切片并修订设计，不猜测兼容规则 |
| Receipt schema 漂移 | **risk** | 只接受 schema v3；未知版本失败封闭并要求新兼容性审查 |
| E1 被误读为可信执行证明 | **risk** | report/README 固定 local-only 限制；不允许 E2 或 CI 宣传 |
| 路径或错误信息泄露 | **risk** | link/junction 拒绝、固定错误报告、sentinel 零泄露测试；发现泄露即 P0 停止 |
