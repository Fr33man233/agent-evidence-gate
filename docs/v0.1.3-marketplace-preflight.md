# v0.1.3 Marketplace Release Preflight

Date: 2026-08-18

## Decision

**GO** for a release-only v0.1.3 patch. The nearest external milestone is a discoverable GitHub Marketplace listing backed by an immutable public release. No verifier behavior, policy contract, adapter, report schema, runtime dependency, or trust claim changes in this version.

## User and business value

- Give maintainers a searchable installation surface instead of requiring repository discovery.
- Give reviewers and the Codex open source fund a direct, runnable GitHub Action entry point.
- Preserve the v0.1 product promise: deterministic, privacy-first, read-only verification with no runtime LLM/API/network use and no candidate-code execution.

## Scope and UX

### Optimize now

- Complete Marketplace-facing metadata in `action.yml`.
- Add one copyable, version-pinned consumer workflow example to the README.
- Keep the release-validation workflow aligned with the published package version.
- Correct stale release-boundary documentation and record rollback instructions.
- Automate consistency checks that prevent metadata, version, workflow, and README drift.

### Defer

- New policies, adapters, profiles, UI, telemetry, analytics, hosted services, paid plans, and moving major-version tags.
- Claims of real production CI identity or independent E2 attestation.
- Additional end-to-end matrices beyond the existing deterministic suite and one controlled read-only GitHub run.

### Remove

- No runtime feature is removed. Stale statements that the repository has no remote or public target are removed from release documentation.

### Risk

- The local historical branch and public `main` have different commit identities even though the pre-release trees match. Publication must be based on the verified public `main` SHA and must not force-push local history.
- GitHub CLI authentication is currently invalid. Re-authentication or the already authenticated GitHub browser session is required for external writes.
- Marketplace publication is immediate and is not a GitHub security review. The listing must not imply verified-creator status or production attestation.

## System boundaries and data contracts

- Frontend/UX boundary: GitHub Marketplace page plus README installation example only.
- Workflow boundary: existing `action.yml` inputs and `dist/action.cjs` entry point remain unchanged.
- Backend/model boundary: none; v0.1.3 adds no service, model, API, database, or network path.
- Data contracts: `agent-task.yml`, `agent-trace.jsonl`, evidence envelopes, canonical profiles, reports, reason codes, and exit codes are unchanged.

## Privacy and security

- No secrets are added or used.
- The Action remains read-only and continues to require only `contents: read`.
- No `pull_request_target`, candidate command execution, raw output ingestion, runtime network, or LLM call is introduced.
- Public documentation must retain the `E2-candidate` limitation and must not describe it as proof of production CI identity.

## Testing and release operations

- Run the metadata/version consistency test through a red-green cycle.
- Run TypeScript checking, the production bundle build, all automated tests, and `git diff --check` from the isolated worktree.
- Confirm the generated Action bundle is unchanged from v0.1.2 because runtime source is unchanged.
- Publish v0.1.3 from the verified public `main` lineage, run the controlled read-only validation once, then enable the Marketplace listing.

## Deployment and rollback

- Deployment is a public `v0.1.3` GitHub Release followed by Marketplace publication.
- Primary Marketplace category: Security. Secondary category: Continuous integration, if offered by the UI.
- Rollback is to remove the Marketplace association from v0.1.3 and instruct consumers to pin `v0.1.2` or its reviewed commit SHA. No database, queue, credential, or migration rollback exists.

## Resource budget and efficiency

- Dependencies added: 0.
- Runtime LLM/API/network calls added: 0.
- Full local verification runs: 1 after implementation, plus the required baseline and focused red-green checks.
- External controlled CI runs: 1.
- Manual publication operations: one release flow and one Marketplace listing flow.
- Expected recurring maintenance cost: one release-version consistency test and ordinary release-note updates.

## Exit criteria

1. Marketplace metadata is complete and valid.
2. README provides a version-pinned consumer example with least-privilege permissions.
3. Package version and controlled workflow both identify v0.1.3.
4. Type check, build, all tests, and diff checks pass from the isolated worktree.
5. Public v0.1.3 release points to the intended public `main` commit.
6. Controlled GitHub validation passes without expanding the E2 claim.
7. Marketplace page is publicly visible and links to the correct repository and release.
