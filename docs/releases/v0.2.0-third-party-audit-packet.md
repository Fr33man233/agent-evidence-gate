# AEG v0.2.0 第三方安全审计包

**用途：** 提供给与实现者无关的安全审计者；本文本身不是审计结论。  
**候选版本：** `0.2.0`，当前仅为本地 RC。  
**公开基线：** v0.1.3 / `d82c7863f48878bfee66e978e7569c464de48ea2`，不得修改。

## 审计边界

审计者应审查当前候选 immutable commit 的源代码、`action.yml`、bundle、测试、设计文档、威胁模型和发布候选记录。审查目标是确认：

- native OMK EvidenceReceipt v3 解析和 digest/state binding 没有越权或 fail-open 路径；
- 输入文件、祖先 link/junction、scope、大小、深度、重复 key 和隐私字段边界失败封闭；
- runtime 没有 secrets、网络、模型、运行时安装、候选命令执行或 shell execution；
- Action 权限与 Node 24 bundle 合同符合设计；
- E1/local-only 报告没有升级为 E2、独立 CI 身份或生产证明；
- 报告、错误和日志不泄露原始 claim、command、cwd、stdout/stderr、environment 或 credential。

## 禁止行为

审计者不得读取或要求提供 secrets、token、个人数据或私有仓库；不得运行 Receipt 中记录的 command，不得执行候选 package/script/test，不得使用 `pull_request_target`，不得向外部服务上传真实仓库内容。只使用仓库内 sanitized fixture 和临时合成 Git 仓库。

## 最小审计步骤

1. 在独立 checkout 固定候选 commit，核对公开 v0.1.3 tag 未变化。
2. 检查依赖 lockfile、Node 24 bundle、`action.yml`、workflow 权限和所有 runtime child-process/network/package-install 路径。
3. 阅读 `docs/superpowers/specs/2026-08-19-native-omk-receipt-v3-design.md`、`docs/threat-model.md`、`docs/reviews/2026-08-19-v0.2.0-security-audit.md`。
4. 运行完整测试、类型检查、两次构建哈希比较、Markdown link check 和静态边界扫描。
5. 对 Receipt parser、path preflight、Git fingerprint、report privacy、CLI/Action contract 做代码审查，并至少复现一个负例：祖先 junction、artifact I/O error、workspace mutation 或 privacy sentinel。
6. 对生产依赖执行独立漏洞数据库复核；当前仓库已用 OSV 检查 `yaml@2.8.3` 与 `esbuild@0.25.9`，但该复核不能替代源代码第三方安全审计。
7. 输出带审计者身份、审查 commit、工具版本、命令、发现、严重度、修复建议和结论的签名或可验证报告。

## 结论格式

审计报告必须明确区分：`pass`、`pass with findings`、`fail`、`not assessed`。任何 P0/P1、隐私泄露、数据边界绕过、确定性回归或候选执行路径都应阻断公开发布。审计报告不得把本地 synthetic pilot 或 E1 Receipt 写成 real E2。

## 当前状态

本项目当前只有仓库内本地审计记录，没有独立第三方审计者、独立工具链或第三方签名报告；因此此门槛仍为 **未满足**。
