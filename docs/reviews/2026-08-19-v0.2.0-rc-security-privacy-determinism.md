## 合同与隐私检查

- Receipt parser 只接受 JSON，不接受 YAML；检查 duplicate key、未知字段、schema version、时间/状态组合、输出 digest 上限、credential、command redaction/HMAC、workspace artifact-set/Git dirty/manifest digest、ledger/attestation shape 和 core digest。
- AEG 不执行 Receipt 中的 command，不运行 candidate package/test/script，不读取 secrets，不调用 LLM/API/network，不创建 OMK ledger、replay database 或执行控制面。
- 报告只输出稳定 ID、digest、固定 reason/remediation 和 E1 限制；不回显 claim、command、absolute cwd/root、stdout/stderr、environment、signature 或 credential。
- `local` 是唯一可通过 profile；`pr`/`protected` 以 `AEG070` 失败，不宣称 E2、独立 CI proof 或 protected-branch control。
- `.github/workflows/release-validation.yml` 已明确固定到公开 v0.1.3 immutable commit，继续验证历史 v0.1 contract；它不调用未发布的 v0.2 Action，也不构成 v0.2 release validation。

- 生产依赖仍只有 `yaml`；未安装完整 OMK package，未把 disposable spike 复制进运行时。

实现仅改变当前隔离工作树文件；没有数据库、ledger 或外部状态迁移。出现 P0 隐私、安全、确定性或数据丢失问题时，停止版本推进并保留最后一次已验证状态；不得放宽校验换取试点通过。
